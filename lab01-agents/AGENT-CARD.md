## 2. Призначення
- **Предметна область**: Коди стану протоколу HTTP (RFC 9110, Section 15; MDN Web Docs; специфікація REST API платформи «Nom-Nom-Save»).
- **Зв'язок із кваліфікаційною роботою**: Бакалаврська кваліфікаційна робота на тему «Розробка серверної частини платформи раціонального споживання та порятунку залишків їжі «Nom-Nom-Save» (nom-nom-save_server)», розділ «Проєктування архітектури та інтерфейсів взаємодії REST API» (Варіант 7).
- **Що робить агент (2-3 речення)**:
  Агент консультує розробників та студентів щодо семантики, правил вибору та коректного застосування кодів відповідей HTTP під час проєктування та реалізації ендпоінтів REST API. Він спирається на перевірені стандарти середовища, запобігає галюцинаціям при запитах про неіснуючі або нестандартні коди та надає конкретні бізнес-приклади (автентифікація, конфлікти замовлень, валідація DTO).
- **Типові запити користувача (3 приклади)**:
  1. «Розкажи детально про HTTP статус 409 Conflict: коли його повертати у Nom-Nom-Save?»
  2. «Порівняй коди стану HTTP 401 Unauthorized та 403 Forbidden: у чому різниця для захисту API?»
  3. «Коли повертати 400 Bad Request, 401 Unauthorized чи 403 Forbidden? Наведи сценарії для замовлення страв у Nom-Nom-Save.»
- **Чого агент не робить (межі)**:
  - Не модифікує файли вихідного коду Express/TypeScript чи схеми Drizzle ORM.
  - Не виконує реальних мережевих HTTP-запитів до зовнішніх серверів чи баз даних.
  - Не ухвалює архітектурних рішень без підтвердження фактами з верифікованого середовища.

## 3. Архітектура
| Дія | Аргументи | Детермінована? | Змінює середовище? |
|---|---|---|---|
| `lookup_http_status` | `code: str` | так | ні |
| `list_status_class` | `status_class: str` | так | ні |
| `finish` | `answer: str` | — | ні |

- **Умови зупинки**:
  1. Команда `finish` від моделі, коли накопичених фактів достатньо для повної відповіді.
  2. Ліміт кроків циклу: `MAX_STEPS = 6`.
  3. Ліміт загальної кількості викликів моделі: `MAX_LLM_CALLS = 8`.
- **Обробка відмов**:
  - Відхилення невідомих дій через білий список `ALLOWED_ACTIONS` у `validator.py`.
  - Перетворення помилок `DecisionError` на спостереження виду `ERROR: ...`, що надає моделі можливість виправити рішення на наступній ітерації.
  - Обробка відсутніх об'єктів маркером `NOT_FOUND` із категоричною забороною вигадувати факти.
  - Переривання нескінченного циклу або недосяжної мети за умовами бюджету `MAX_STEPS` та `MAX_LLM_CALLS`.

## 7. Відомі обмеження та ризики
- **OWASP LLM01 (Prompt Injection)**: Недовірений текст у запитах користувача не може вийти за межі білого списку дій, оскільки валідатор та диспетчер суворо контролюють дозволений простір операцій.
- **OWASP LLM05 (Improper Output Handling)**: JSON-відповідь моделі валідується до передачі диспетчеру; синтаксичні та семантичні помилки перехоплюються блоком `except DecisionError`.
- **OWASP LLM06 (Excessive Agency)**: Простір дій звужено до двох операцій читання (`lookup_http_status`, `list_status_class`) та дії завершення `finish`.
- **OWASP LLM09 (Misinformation)**: Запобігається маркером `NOT_FOUND` та суворими правилами системної інструкції.
- **OWASP LLM10 (Unbounded Consumption)**: Обмеження кількості ітерацій `MAX_STEPS` та кількості викликів моделі `MAX_LLM_CALLS`.
