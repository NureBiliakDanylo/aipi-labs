# REST Architectural Constraints

REST (Representational State Transfer) — архітектурний стиль для розподілених гіпермедіа систем, побудований на шести строгих обмеженнях.

## Ключові положення
1. **Клієнт-Сервер**: чітке розмежування інтерфейсу користувача та керування даними, що підвищує масштабованість.
2. **Stateless (Без збереження стану)**: кожен запит від клієнта повинен містити всю необхідну інформацію для обробки; стан сесії зберігається на клієнті.
3. **Кешування**: відповіді мають явно позначати себе як кешовані або ні (заголовки `Cache-Control`, `ETag`).
4. **Єдиний інтерфейс (Uniform Interface)**: ідентифікація ресурсів через URI, маніпулювання через представлення, самоописні повідомлення та HATEOAS.
5. **Багаторівнева система**: клієнт не знає, чи підключений він напряму до кінцевого сервера чи проміжного проксі/шлюзу.

## Приклад
У системі Nom-Nom-Save принцип Stateless забезпечується передачею JWT-токена в заголовку `Authorization: Bearer <token>`. Сервер не тримає сесійних сесій у пам'яті, що дає змогу горизонтально масштабувати вузли бекенду.
